# Фабрика аккаунтов

Отдельный бот для добавления Telegram-аккаунтов по номеру+коду. Копит их в один
растущий файл `.backup`, который напрямую импортируется в трекер (тот же формат,
тот же `SESSION_BACKUP_KEY`). Нумерация `session_NNN` продолжается от загруженного набора.

## Как пользоваться

1. (опционально) пришли боту стартовый `.backup` файлом — он подхватит аккаунты и
   продолжит нумерацию со следующего номера.
2. `/add` → номер → код из Telegram → (пароль 2FA, если включён).
3. После успеха бот пришлёт **обновлённый `.backup`** — его заливаешь в трекер
   (трекер принимает `.backup` документом в личке).
4. `/backup` — получить текущий файл. `/count` — сколько аккаунтов.

> Код приходит так же, как в трекере: на флагнутые номера Telegram его не
> доставляет. Фабрика удобна для нумерации и выгрузки, но доставку кода не меняет —
> добавляй на номерах, которые реально получают код.

## Деплой на Render (секреты — только в дашборде, НЕ в репозитории)

Репозиторий публичный, поэтому токен/ключ в код не коммитятся. Создай на Render
сервис из этого репозитория (Docker) и задай переменные окружения:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен бота @heisoqqkqbot |
| `API_ID` | тот же, что у трекера |
| `API_HASH` | тот же, что у трекера |
| `SESSION_BACKUP_KEY` | **тот же, что у трекера** (иначе `.backup` не импортируется) |
| `ADMIN_IDS` | твой Telegram ID (через запятую, если несколько) |
| `START_INDEX` | `207` (с какого номера начинать, если нет стартового файла) |

`render.yaml` уже описывает сервис — при подключении репозитория Render предложит
эти переменные, останется вписать значения.
